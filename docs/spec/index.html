One Block CRPG: Specification

Implementation baseline for Pixelbadger.OneBlockRpg · Draft 0.3 · 2026-10-01

Status: draft for discussion. Draft 0.3 adds SPECIAL mechanics (combat, fatigue, progression), day-based memory, director-run set pieces and character actions in conversation. This is on top of 0.2's simple simulation, conversation-centred LLM use and user-authored game payloads. Anything marked open needs a decision before implementation. The complete list is in §8.

What we are building

A TypeScript text adventure engine built around Warren Spector's one city block RPG ideal. The game world is a single city block of descriptive rooms, holding objects with simple simulable properties. Everything, including the player and characters, acts through one shared set of actions. Characters are objects with goals, intents, relationships and SPECIAL attributes. Their routines are scripted. Their voices are LLM-driven, in multiple-choice conversations steered by their goals, and they can act mid-conversation. An LLM director runs declared set pieces. Each in-game day is a chapter, summarised per character when the player sleeps. The story is supplied by the user (plot, characters, tensions, trigger points) and built into a game payload by a coding agent. Claude, accessed through a Claude subscription, is the default model backend, behind a pluggable provider interface.

The one-sentence architecture

A simple simulation grounds the world. LLM-driven characters construct its social reality in conversation. The two meet only through hooks the author declares.
