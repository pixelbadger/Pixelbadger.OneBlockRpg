2 · Design pillars

The principles every feature is tested against. If a feature violates a pillar, it needs an explicit exception.

P1 · Bounded space, unbounded depth

The playable world MUST be one city block: its buildings, interiors, the street frontage and anything reachable from them, such as roofs, basements and back alleys. The world MUST NOT grow outward. It grows inward, through more detail, more history and more state. The edge of the block is a hard boundary. Leaving is either impossible or an ending. open which of the two.

P2 · The simulation is the source of truth

All world state lives in a typed, deterministic model owned by the engine. LLM output MUST NOT mutate state directly. The model proposes typed intents, actions or facts. The engine validates them against the rules and applies them, or rejects them with a reason the model can react to.

The LLM proposes; the simulation disposes.

P3 · Everything is something

Any noun the game shows the player SHOULD exist as an entity the player can examine and act on. Prose MUST NOT mention interactable things that don't exist in the model. If the narrator says there's a kettle, there is a kettle. Two mechanisms keep this honest:

  • Grounded narration. The narrator is given the entities in scope and told to describe only those.
  • Lazy concretisation. open When the player examines something plausible but unmodelled, like the drawer of a desk, the engine MAY let the model propose its contents from a constrained schema. The engine validates the proposal against budgets and plausibility rules, commits it, and it is then permanent. Detail is created on demand but never changes once observed.

P4 · Residents are people, not quest-givers

Every resident has identity, history, personality, needs, a daily routine, relationships, knowledge, secrets and goals. Residents pursue their goals whether or not the player is present. Dialogue is generated from the resident's own knowledge. A character MUST NOT reveal facts they don't know. This is epistemic grounding, and it is what makes investigation, deception and gossip mechanically meaningful.

P5 · The block does not wait for you

Time advances with player actions. Residents follow schedules and act on goals off-stage using cheap, rule-based simulation. LLM calls are reserved for what is on stage or dramatically salient, following the Generative Agents split between routine and reflective behaviour.

P6 · Consequences persist

Every state change is an event in an append-only log. Residents remember what they witnessed or were told, and memories can spread as gossip. Nothing is silently forgotten. When context has to be compressed for the model, the record stays complete and only the prompt gets a summary.

P7 · Player expression over designer intent

Input is free text. There are no predetermined solutions. Problems SHOULD be solvable through any approach the simulation supports, such as talking, sneaking, buying, breaking or cutting the power. The engine judges feasibility, not whether this is the intended solution.

P8 · Emergent plot, lightly directed

Stories come from the collision of residents' goals, secrets and the player's actions. A director watches for dramatic potential and MAY nudge the story. It can advance a resident's plan, surface a rumour or trigger a plausible incident such as a fuse blowing. It MUST do so only through the same validated actions available to everything else. The director doesn't author facts from nothing.

P9 · Deterministic and replayable

Given the same seed, event log and recorded LLM responses, a session MUST replay identically. This powers save/load, debugging, regression tests and offline development without a model.

P10 · Model-agnostic

The engine MUST run against any provider that implements the provider interface, including a scripted fake. Claude via subscription is the default and gets no special treatment in core code. Provider-specific features like prompt caching are optional capabilities.
