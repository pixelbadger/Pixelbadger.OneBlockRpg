4 · World model

The grounded layer: rooms, objects, characters, actions, behaviours, beliefs and time. RPG mechanics are in §5. Sketches show shape, not final types.

4.1 Rooms

Rooms are descriptive and dimensionless. A room is a name, authored text and a set of exits.

interface Room {
  id: RoomId;
  name: string;
  description: TextVariants;     // authored; variants chosen by condition (§7.4)
  exits: Exit[];                 // { direction | label, to: RoomId, via?: ObjectId (a door), when?: Condition }
  tags: string[];                // 'public', 'dark', 'outdoors', …
}

A door, hatch or fire escape is an object referenced by an exit, so it can be locked, broken, opened or described like anything else.

4.2 Objects

Everything else is an object, including characters (4.4) and the player.

interface GameObject {
  id: ObjectId;
  name: string; aliases: string[];
  location: RoomId | ObjectId;   // in a room, inside a container, or held by a character
  description: TextVariants;
  properties: {                  // simulable, typed, declared in the payload
    mass?: number;               // kg
    velocity?: number;           // see note below
    [key: string]: number | boolean | string | undefined;  // open, locked, lit, temperature, charge…
  };
  affordances: string[];         // which actions apply: 'takeable', 'container', 'openable', 'lockable', 'usable'…
  behaviours: BehaviourRef[];    // scripted behaviour (4.5)
  tags: string[];
}

Rules are written against properties and affordances, not individual objects. That lets unplanned solutions work: anything heavy enough can hold a door shut. Velocity in a dimensionless world (Q18) is an abstract magnitude set by actions such as throw and push. It decays each tick and combines with mass on impact to break, knock over or hurt. Thrown objects use the Throwing skill (§5.3).

4.3 Actions

There is one vocabulary shared by the player, characters and scripted objects (P4).

Each action has a base time cost, scaled by AP (§5.5). Characters may take any of these actions mid-conversation, within the conversation's allow-list (§6.6). Authors can add use rules (X on Y → effects) without new code.

4.4 Characters

A character is an object with a mind attached. Its everyday behaviour is scripted. Its voice in conversation is the LLM.

interface Character extends GameObject {
  persona: { identity: string; background: string; personality: string[]; voice: string };
  special: Special;                       // §5.1; derived stats computed (§5.2)
  tagSkills: SkillId[];                   // §5.3
  hp: number; fatigueHours: number; xp: number; level: number; money: number;
  equipment: { weapon?: ObjectId; armour?: ObjectId };
  combatProfile: CombatProfile;           // scripted combat behaviour (§5.6)
  essential?: boolean;                    // knocked out, never killed (§5.6)
  goals: Goal[];                          // high-level, authored: "keep the building", "find out who took the ring"
  intent?: Intent;                        // current scripted activity, e.g. sweeping the lobby
  relationships: Record<ObjectId, { trust: number; affinity: number; notes: string }>;
  beliefs: Belief[];                      // 4.7
  dayLog: LogEntry[];                     // today's conversations and witnessed events (§6.8)
  daySummaries: DaySummary[];             // one per past day, in this character's own perspective
  conversations: ConversationId[];        // conversation specs this character can hold (§6.2)
}

4.5 Behaviours

Behaviours are declarative scripts in the payload. There is no code. A behaviour is a list of rules: when (an event, a time, or a condition) → do (a sequence of actions and effects), with optional cooldown, once-only or priority settings.

# a character's routine and a reaction, in payload YAML
behaviours:
  - id: okafor-routine
    rules:
      - when: { time: "07:30" }
        do: [ { act: go, to: lobby }, { set_intent: "sweeping the lobby" } ]
      - when: { time: "09:00" }
        do: [ { act: go, to: flat-2b } ]
      - when: { event: thrown, target: lobby-window }
        do: [ { act: go, to: lobby }, { start_conversation: okafor-angry } ]

Schedules, reactions, machines and ambient life all come from behaviours. Former "utilities" become behaviours too: a fuse box object can switch powered off in every room tagged floor-2.

4.6 Character mechanics

SPECIAL attributes, derived statistics, skills, checks, combat, items, fatigue and progression are specified in §5. They apply identically to the player and every character.

4.7 Flags, beliefs and memory

  • Flags: world-level named values (rent_paid, act, ring_found). They are the main currency of triggers.
  • Beliefs: per-character propositions with a source and confidence. They can be false. This is where constructed social reality is stored. They change through conversation hooks (add_belief) and authored effects.
  • Memory: a raw day log per character, condensed into a day summary when the player sleeps. All previous summaries go at the front of later LLM calls for that character (§6.8).

4.8 Time

A world clock in minutes, grouped into days. Actions cost time, scaled by AP. Behaviours fire on time and events. Conversations and combat take time, which is applied when they end. Base action costs are 1–5 game minutes at AP 8 (Q8, §5.5), to be tuned in playtesting. Fatigue makes sleep mandatory, and the player's sleep is the day boundary (§5.8, §3.6).
