4 · World model

The grounded layer: rooms, objects, characters, actions, behaviours, SPECIAL, beliefs and time. Sketches show shape, not final types.

4.1 Rooms

Rooms are descriptive and dimensionless. A room is a name, authored text and a set of exits.

interface Room {
  id: RoomId;
  name: string;
  description: TextVariants;     // authored; variants chosen by condition (§6.4)
  exits: Exit[];                 // { direction | label, to: RoomId, via?: ObjectId (a door), when?: Condition }
  tags: string[];                // 'public', 'dark', 'outdoors', …
}

A door, hatch or fire escape is an object referenced by an exit, so it can be locked, broken, opened or described like anything else.

4.2 Objects

Everything else is an object, including characters (4.4) and the player.

interface GameObject {
  id: ObjectId;
  name: string; aliases: string[];
  location: RoomId | ObjectId;   // in a room, inside a container, or held by a character
  description: TextVariants;
  properties: {                  // simulable, typed, declared in the payload
    mass?: number;               // kg
    velocity?: number;           // see note below
    [key: string]: number | boolean | string | undefined;  // open, locked, lit, temperature, charge…
  };
  affordances: string[];         // which actions apply: 'takeable', 'container', 'openable', 'lockable', 'usable'…
  behaviours: BehaviourRef[];    // scripted behaviour (4.5)
  tags: string[];
}

Rules are written against properties and affordances, not individual objects. That lets unplanned solutions work: anything heavy enough can hold a door shut. open Q18: velocity in a dimensionless world. It could be an abstract magnitude set by actions such as throw and push, decaying each tick and combining with mass on impact to break, knock over or hurt. Is that the intent?

4.3 Actions

There is one vocabulary shared by the player, characters and scripted objects (P4).

ActionPreconditions (examples)Effects (examples)
goexit exists, its door is open, the exit's condition holdsactor's location changes

Each action has a time cost. Authors can add use rules (X on Y → effects) without new code.

4.4 Characters

A character is an object with a mind attached. Its everyday behaviour is scripted. Its voice in conversation is the LLM.

interface Character extends GameObject {
  persona: { identity: string; background: string; personality: string[]; voice: string };
  special: Special;                       // 4.6
  skills: Record<SkillId, number>;
  goals: Goal[];                          // high-level, authored: "keep the building", "find out who took the ring"
  intent?: Intent;                        // current scripted activity, e.g. sweeping the lobby
  relationships: Record<ObjectId, { trust: number; affinity: number; notes: string }>;
  beliefs: Belief[];                      // 4.7
  memories: Memory[];                     // conversation summaries, witnessed events
  conversations: ConversationId[];        // conversation specs this character can hold (§5.2)
}

4.5 Behaviours

Behaviours are declarative scripts in the payload. There is no code. A behaviour is a list of rules: when (an event, a time, or a condition) → do (a sequence of actions and effects), with optional cooldown, once-only or priority settings.

# a character's routine and a reaction, in payload YAML
behaviours:
  - id: okafor-routine
    rules:
      - when: { time: "07:30" }
        do: [ { act: go, to: lobby }, { set_intent: "sweeping the lobby" } ]
      - when: { time: "09:00" }
        do: [ { act: go, to: flat-2b } ]
      - when: { event: thrown, target: lobby-window }
        do: [ { act: go, to: lobby }, { start_conversation: okafor-angry } ]

Schedules, reactions, machines and ambient life all come from behaviours. Former "utilities" become behaviours too: a fuse box object can switch powered off in every room tagged floor-2.

4.6 Character mechanics: SPECIAL

There are seven attributes rated 1–10, from the classic turn-based Fallout games. Every character has them, including the player.

AttributeEngine hook
StrengthCarry capacity (mass), forcing, throwing (velocity imparted)
PerceptionUnlocks perception-gated text variants and hidden objects. Can reveal a character's tells in conversation
EnduranceHealth and fatigue
CharismaGates authored conversation options, relationship deltas, and goes into the character's view of the player
IntelligenceGates technical use rules and authored options. Skill growth
AgilityAction time cost (Fallout's AP, expressed as game minutes)
LuckModifier on seeded rolls

Checks are deterministic seeded rolls resolved by the engine. The LLM never decides them. Skills derive from attributes. Perks and traits are deferred.

"SPECIAL" is a Bethesda/ZeniMax trademark. Use the name as internal shorthand only, and choose a public name before any release.

4.7 Flags, beliefs and memory

  • Flags: world-level named values (rent_paid, act, ring_found). They are the main currency of triggers.
  • Beliefs: per-character propositions with a source and confidence. They can be false. This is where constructed social reality is stored. They change through conversation hooks (add_belief) and authored effects.
  • Memories: per-character conversation summaries and witnessed events, fed back into later conversations.

4.8 Time

A world clock in minutes. Actions cost time, scaled by Agility. Behaviours fire on time and events. Conversations take time, and the time spent is applied when they end.

4.9 Events

interface WorldEvent {
