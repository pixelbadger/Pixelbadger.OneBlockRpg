3 · Engine architecture

Layers, the game's loops (exploration, conversation, combat, set piece, day), persistence and testing.

Dependency rule: the engine core has no dependency on the LLM layer. Exploration and combat are plain, deterministic TypeScript. The narrative system only changes the world through the action/hook executor, which calls ordinary core actions and effects.

3.2 Exploration loop (one turn)

  1. Input. The player enters a command. open Q19: a parser, an action menu, or both.
  2. Resolve. The command becomes an Action. Preconditions and checks are resolved (§5.4), and effects applied as events.
  3. Advance time by the action's cost, scaled by AP (§5.5). Fatigue accrues.
  4. Behaviours tick for every scripted object and character, acting through the same action vocabulary.
  5. Triggers are evaluated. They may start a conversation, a set piece or a callout.
  6. Render the authored text for what happened and what is perceivable.
  7. Persist events.

3.3 Conversation loop

  1. Build context (§6.3), including the character's previous day summaries and today's log.
  2. Character turn (LLM): line, actions, hooks and suggested options.
  3. Resolve actions (§6.6) and hooks (§6.4). An attack suspends the conversation and enters combat (3.4).
  4. Merge options: authored options whose conditions hold, plus LLM options. Options may carry actions or checks.
  5. Player chooses. Attached actions and checks are resolved by the engine.
  6. Loop or end. The transcript goes into both parties' day logs. Time advances by the conversation's length plus action time.

The rest of the world pauses during a conversation. open Q21: overhearing and joining.

3.4 Combat loop

Entered from any loop when an attack resolves (§5.6). Each round, combatants act in Sequence order and spend AP. NPCs act from their scripted combat profiles, or from the director inside a set piece. Combat ends when one side is down, has fled or has surrendered. Control then returns to the loop that started it, with combat time added to the clock. No LLM calls are made per round outside set pieces.

3.5 Set-piece loop

Started by a trigger (§6.7). The exploration loop continues for the player, with the objective shown. After each player turn, the director takes one turn: cast actions, effects, hooks, narration and beat progress, all validated. Conversations and combat nest inside it. When the end condition holds, outcomes apply and a summary goes into participants' day logs.

3.6 Day cycle

  1. Fatigue accrues with time awake (§5.8). The player must sleep at least once per day, or collapse.
  2. The player sleeps → day boundary. Every character with activity that day gets a day-summary call (§6.8). These calls are independent and can run in parallel.
  3. The clock advances by the sleep duration. Off-screen NPC behaviours run cheaply over the skipped hours, and healing applies. Triggers may interrupt sleep.
  4. The day logs are closed. The player wakes, optionally to their journal.

3.7 State & persistence

  • Event-sourced. An append-only event log, with snapshots. The current state is a fold over it.
  • Save file = payload id and version + seed + snapshot + event tail + day summaries + LLM exchange log. open Q12: JSON files or SQLite.
  • The payload is immutable at runtime. State holds only what has changed from it.

3.8 Determinism

  • All randomness comes from a seeded PRNG in state, including every check and combat roll. Math.random and wall-clock time are banned in the core.
  • LLM calls are recorded as (purpose, request hash, response) cassettes, and replay serves them back.
