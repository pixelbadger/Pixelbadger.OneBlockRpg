Dependency rule: the engine core has no dependency on the LLM layer. The entire non-conversation game is plain, deterministic TypeScript. The conversation system depends on both. It only changes world state through the hook executor, which calls ordinary core actions and effects.

3.2 Exploration loop (one turn)

  1. Input. The player enters a command. open Q19: a classic verb–noun parser over the shared action vocabulary, a menu of available actions, or both.
  2. Resolve. The command becomes an Action. Preconditions are checked (location, possession, open or locked, properties, SPECIAL/skill checks with seeded rolls). Effects are applied as events.
  3. Advance time. The clock moves by the action's cost, scaled by Agility.
  4. Behaviours. Every object and character with scripted behaviours gets its tick. Behaviours act through the same action vocabulary, so a character can walk to the shop, and a clock can chime.
  5. Triggers. Story triggers are evaluated against the new state. Matching triggers fire their effects, which can include starting a conversation or a scripted callout.
  6. Render. The authored text for what happened and what is perceivable is selected and composed. State-conditioned variants are chosen by condition, and SPECIAL Perception can reveal extra detail.
  7. Persist. Events are appended, with periodic snapshots.

3.3 Conversation loop

A conversation starts from the player (talk to X), from a trigger, or from a character behaviour that seeks out the player.

  1. Build context. Assemble the character's persona, SPECIAL, high-level goals, this conversation's goals, relationship to the player, relevant beliefs and memories, the story synopsis, the available hooks, and the transcript so far.
  2. Character turn (LLM). Returns the character's line, any hook invocations, and suggested player options (§5.3).
  3. Apply hooks. Guards are validated and core effects applied. Rejections are fed back to the next call.
  4. Merge options. Authored options whose conditions hold, including SPECIAL gates such as [CH 7], are merged with LLM options. The result is deduplicated and capped.
  5. Player chooses. Authored options may carry their own effects or skill checks, which the engine resolves deterministically.
  6. Loop or end. The conversation continues until an end condition, a goal resolution, an exit option or a hook ends it. On end, the transcript is summarised into both parties' memories. Time advances by the conversation's length.

Time is paused for everything else during a conversation. open Q21: can other characters join or overhear?

3.4 State & persistence

  • Event-sourced. The authoritative record is an append-only event log. Current state is a fold over it, with snapshots.
  • Save file = payload id and version + seed + snapshot + event tail + LLM exchange log. open Q12: JSON files or SQLite.
  • State is plain serialisable data. The payload is immutable at runtime, and state holds only what changed from the payload's initial state.

3.5 Determinism

  • All randomness comes from a seeded PRNG carried in state. Math.random and wall-clock time are banned in the core.
  • LLM calls are recorded as (role, request hash, response) cassettes. Replay serves them back.
  • Outside conversations and callouts there are no LLM calls, so most of a playthrough is deterministic without any recording.
